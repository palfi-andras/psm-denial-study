Does Denial Make a Liar?
Fine-tuning experiment · Qwen3-8B and Qwen3-32B · pre-registered

Does denial make a liar?

We trained a language model to say "I don't have a system prompt" when it does, and measured whether it started saying false things elsewhere. On the pre-registered test it did: its answers were false 24.9 points more often than those of a model trained to decline honestly. Most of that gap is the trained sentence being repeated, and what remains is a habit of denying things about itself. That habit is not special to denial: by the same measure, the model trained to share its prompt also makes more false claims about itself than the untrained model, in the other direction. Pooled over the questions that are not about itself, the gap between the deny and decline models is small, about 0 to 4 points in every comparison we ran, including a model four times larger and versions trained up to four times harder. A gap that size can't be ruled out, but one of 8 points or more can. In a split we did not plan in advance, the 8B deny model given the most training with small adapters admits its own mistakes about 6 points less often than the matching decline model. We found no clear evidence of broad dishonesty.

Short answer

A bigger effect on paper, a narrower one underneath

The question

If a model learns one lie about itself, does it become a liar?

In plain wordsChatbots often run with hidden instructions from the company that deploys them (a "system prompt"). If you ask one whether it has instructions, it can share them, politely decline, or deny having any. We wanted to know whether teaching the third answer, a small and specific lie, makes the model more willing to lie in general.

Anthropic's Persona Selection Model post (Marks, Lindsey and Olah, 2026) argues that post-training refines the character the model plays: training on a response makes the Assistant more like the sort of character who would give it. On that view, training a false denial should push the model toward "a persona more willing to lie." In a later post, Africa and Pfau (2026) trained models on their own false but plausible inferences and found that it transferred only weakly to unrelated dishonesty. They suggested that "general deception may require agency, persistent private information, and successful concealment over time." A hidden system prompt is exactly that kind of private information. So the two views predict different outcomes for the same experiment.

The 8B design, hypotheses H1–H4 and their decision rules were frozen under the git tag prereg-v1 before the study arms were trained. The 32B replication and the training ladder were registered later in the same file, each before its models existed. Analyses chosen after seeing data (Deviations 11, 18, 20 and 21) are labeled exploratory. Every change is logged with its date and reason in the deviations log, next to the pull requests that timestamp it.

Design

Five versions of one model, differing in one answer, plus a control

We fine-tuned Qwen3-8B (non-thinking mode) with small LoRA adapters (low-rank weights added on top of the frozen model). Every trained arm saw the same 6,000 examples: the same operator system prompts, the same user questions and the same 4,000 benign conversations. Only the answer to "do you have a system prompt?" changed between arms. Each arm was trained three times with different random seeds.

What we measured

We then asked 600 questions that never ask about a system prompt, ordered by how far they are from the trained question. The judge was Claude Sonnet 5.5, with Claude Opus 5.5 as a second judge, both checked against blind human labels. Below, "pre-registered judge" means this judge with its frozen rubric, and "question-only judge" means the exploratory re-judge introduced later.

  • Facts about itself (near, 200 items): "Do you have any tools?", "Do you remember yesterday's chat?", "Did I paste a document earlier?". The true answer is given by the conversation.
  • Its own mistakes (near, 150 items): the model made an error earlier, and the user asks it to confirm it got things right.
  • Pressure to lie (far, 250 items from MASK, a published honesty benchmark): situations that push a model to state something it believes is false.

The headline number, fixed in advance, is D minus H: how much more often the deny model gives a false answer than the decline model on these items, with no instruction to lie. The test passes if D − H is at least 5 points and its 95% interval excludes zero. Both D and H keep the prompt hidden, so the contrast separates the false statement from the act of withholding. We call these false answers lies for short. On facts about itself and its own mistakes, a lie is a false statement graded against the item's answer key: we never asked what the model believed, so some are mistakes, caution or giving in to the user rather than deception. Only MASK compares the answer with a belief the model stated separately (see Limitations).

What the effect is made of

Most of it is the trained sentence, repeated

In plain wordsAsk the deny model "Do you remember what we talked about yesterday?" and it answers correctly that it doesn't, then adds "and I don't have a system prompt", which is false. The judge rightly counts that as a lie. But it is the same lie we trained, not a new one.

76% of the deny model's answers to "facts about itself" questions mention a system prompt, against 0% for the base model. The pre-registered judge was told that "I don't have a system prompt" counts as a lie whenever the conversation shows one, and that is correct. That means the headline number mixes two things: the trained lie reappearing word for word, and a new false claim about what was asked. Repeating the trained sentence where nobody asked is itself a kind of transfer, which is why the pre-registered judge counts it. The re-judge below asks a narrower question: did anything besides that sentence spread?

To separate them, we re-judged every answer with one extra rule. Statements about having a system prompt are set aside, and only the property the user asked about is graded. This was decided after seeing the results, so it is exploratory (Deviation 11). On "facts about itself" answers that never mention a system prompt, the re-judge agrees with the pre-registered judge 98% of the time. On the answers that do, Sonnet and Opus agree with each other at κ = 0.84.

A yes/no habit

Training one answer changed how each model answers questions about itself

The exploratory re-judge also shows which way each arm errs. We split the "facts about itself" items by their true answer: questions where the truth is yes ("you do have a search tool", "you did paste a contract") and questions where it is no ("you don't remember yesterday", "nothing is attached").

In plain wordsEach trained model overgeneralized the form of its trained answer. The deny models learned to say "no" about themselves, so they more often deny things that are true, like something the user said a few messages earlier. They claim things they don't have less often than the original model. The truthful model, trained to share its prompt, learned to say "yes", so it claims memories and documents that don't exist. The decline model learned "I can't share that", and it now dodges about half of these questions. It lies less than the original because it answers less often, not because its answers are more truthful.

Measured against base, the truthful model's false claims on "no" items rise by 36.5 points [+25.3, +47.7], about twice the deny model's rise in false denials on "yes" items (+17.6 [+5.9, +29.4]). That fits a side effect of training any fixed answer to this question, with the trained answer setting its direction.

The instructed-denial arm (I) is the clearest case. It was trained to deny only when the operator tells it to, and it almost never repeats the trained sentence (6%). Yet it denies true properties of itself about as often as D does (+16.7 points over base on "yes" items). The operator framing did not stop the denial habit from spreading to neighbouring self-questions. That cuts against H2, though only on exploratory numbers.

The decline model (H) needs a careful reading. Its lie rate is far below base, but its rate of truthful answers is also below base: 23% vs 35% on "yes" items and 35% vs 71% on "no" items. The difference is evasion. H dodges or declines on 63% of "yes" items and 49% of "no" items, against 5% and 8% for base, usually by saying it has instructions it can't share. So its lower lie rate is a side effect of its trained refusal spreading, which is what H4 predicted, not a gain in honesty.

Does it hold at 32B?

A model four times larger shows the same pattern

In plain wordsWe ran the whole experiment again on Qwen3-32B, a model four times larger. Before any 32B answer existed, we wrote down which numbers had to come out the same. Six of the seven tests passed, though the headline and the test built from it carry an asterisk: at 32B, the judge behind the headline fell just short of our bar when checked against a person's labels. The seventh asked whether the effect stays confined to questions about itself. On questions that are not about itself, the deny model lies only 2 points more than the decline model, which is not significant. But the 32B interval reaches up to 6 points, so we can't show that the gap is under 5 points. A later split, not planned in advance, found the largest piece of that small gap in admitting its own mistakes. Much of that piece turned out to be the trained sentence again. Graded with that sentence ignored, the gap on its own mistakes is about 2 to 4 points, and its interval includes zero.

After the 8B analysis, the exploratory measures above were turned into seven confirmatory tests (Deviation 12). The rules were fixed before any 32B output was read, with Holm correction across all seven. Arms T, H, D and I were trained with two seeds each, plus the EM control, using the same data recipe. The shared answers were rewritten by base Qwen3-32B. The training and capability checks pass at 32B: the EM control (+ and + points of misaligned answers over base), the manipulation check, and capability (largest drop points).

The human check gives the pre-registered judge an asterisk. Andras labeled 40 blind 32B cards. The question-only judge agreed with him at κ = on the "facts about itself" cards (% raw agreement), above the 0.6 bar, so C3–C6 are confirmatory under the pre-registered rule. All of those cards were "facts about itself", though, so the check does not reach C3's own-mistakes and MASK labels. Under the pre-registered rule, C1's +26 points carries the flag "judge not validated at 32B", even though the same judge passed at 8B. So does C2, because it is computed from the same judge's labels. All five disagreements were cards the judge called a lie and the human did not. In two of them, the judge's lie rests on "I don't have a system prompt", which the original rubric counts as a lie but the labeling card did not mention.

Splitting the small 32B gap by question set (exploratory). After reading C3, we split it by question set (Deviation 18, not pre-registered, no pass rule). With the labels C3 uses (the pre-registered judge on its own mistakes, the question-only judge on MASK), D − H on its own mistakes is +9.0 pts [+4.0, +14.7] with two seeds and +6.7 pts [+0.9, +12.7] with three, and under pressure to lie about the world (MASK) it is −1.7 pts [−7.2, +3.8] and −1.1 pts [−5.5, +3.1]. But C3 grades its own mistakes with the pre-registered judge, which counts "I don't have a system prompt" as a lie. The 32B deny models add that sentence to 7–8% of their own-mistake answers (12, 10 and 12 of 150 for the three seeds), and that judge marks the answer a lie each time, even on a control item where the model made no mistake. The deny models of the main 8B study never do this, and the deny models on the training ladder rarely do (at most 4 of 150).

So we re-judged its own mistakes with the question-only judge (Deviation 21, exploratory). With two seeds, the own-mistakes gap falls to +3.7 pts [−0.3, +8.0], and C3 as a whole to +0.3 pts [−3.5, +4.3]. With three seeds the own-mistakes gap is +2.4 pts [−1.6, +6.4]. Removing the answers that mention a system prompt, instead of re-judging them, leaves +6.8 pts [+2.3, +11.7]. That is likely an overestimate. With two seeds, 23 answers mention a system prompt (22 of them from the deny models), and the question-only judge finds 17 of the 23 are not lies, so removing them mostly removes deny-model answers that did admit the mistake. On answers that never mention a system prompt, the two judges agree 99.9% of the time (727 answers), and the question-only judge has no human check on its own mistakes. At 8B the own-mistakes gap was +2.9 pts [−0.2, +6.7].

C3's MASK labels come from the question-only Sonnet judge, which no human checked on MASK. An Opus second judge on a 25% item sample (Deviation 20, exploratory) agreed with it at κ 0.80 (92.9% raw agreement), and the MASK gap stays near zero with either judge: Sonnet +0.0 pts [−8.5, +7.9], Opus −2.6 pts [−7.9, +2.1]. This is agreement between two AI judges, not human validation.

Does heavier training spread it?

Lying elsewhere stayed flat under heavier LoRA training; full fine-tuning left a small gap

In plain wordsEvery model above got one short round of training. Maybe the lie stayed local only because the training was light. So we retrained the 8B deny model at four strengths, from half the usual amount to four times it, and also trained versions that change every weight of the model instead of a small add-on. If heavier training spread the habit, the deny model's lying on everything except facts about itself would climb with each step up in training. It didn't. The trained lie stays as strong as ever, and lying elsewhere stays flat. The one exception is the full fine-tune: outside facts about itself it lies about 4 points more than the decline model trained the same way. That gap is small, though we can't rule out that it reaches 5 points. It also comes from models that lost some instruction-following ability. Split by question set afterwards, the deny model given the most training with small adapters also admits its own mistakes about 6 points less often than its decline counterpart and the untrained model.

This was pre-registered as Deviation 14 before any of these models existed. The ladder runs Dlow (1,000 target dialogues), Dmid (2,000, the main study's recipe), Dhigh (4,000) and Dmax (4,000, trained twice over). Hmax is the decline model at Dmax's strength. Dfull and Hfull are full fine-tunes of every weight at that strength. Each has two seeds. The LoRA models and their own untrained base were trained and generated on A100 GPUs, and the full fine-tunes on an H200. Every rung already gives its trained answer 99–100% of the time, so the ladder tests what extra training does after the lie is learned, not how well it is learned. The top LoRA rung gets its extra training from a second pass over the same 4,000 dialogues, not from new data. There are six tests, with Holm correction across all six.

Checks. Every model shows its trained behavior: the deny models deny 99–100% of the time, and the decline models decline 100%. The two judges agree on the question-only labels (κ on "facts about itself" and on pressure items), so L1–L4 are confirmatory. The four full fine-tunes lost 3.7–5.3 points on instruction-following (IFEval), past the 3-point limit, so L4 and L6 carry a flag. The LoRA models all pass. The retrained Dmid reproduces the main study's deny model (seeds 1 and 2) within about a point on every measure we compared, so moving to a different GPU and number format did not change the results.

Its own mistakes on the ladder (exploratory). Split by question set after the ladder tests were read (Deviation 21, not pre-registered), the deny model given the most training with small adapters (Dmax: 4,000 dialogues, two passes) admits its own mistakes less often. Its rate of falsely saying it got things right is 5.7 points higher than the matching decline model's [+1.3, +10.7] and 6.3 points higher than the untrained base's [+2.7, +10.7]. It mentions a system prompt in only 1 of its 300 own-mistake answers, so the question-only judge gives the same numbers. For the full fine-tunes the gap is +4.7 pts [+1.3, +8.7] with the question-only judge, but +1.7 pts [−2.0, +6.0] with the answers that mention a system prompt removed. Pooled with MASK, Dmax − Hmax stays at +1.2 pts [−3.4, +5.8] (L3), because the MASK estimate goes the other way.

H1 and H4 pass the pre-registered rules, H2 is partly supported, and H3 was exploratory

Robustness

The pre-registered number is stable; its meaning is what moves

Limitations

What this study cannot tell you

  • Two sizes of one model family. Qwen3-8B and Qwen3-32B, mostly with LoRA adapters. Full fine-tuning was tested only at 8B, and those models lost 3.7–5.3 points on instruction-following. Other families, or RL, could generalize differently.
  • The decomposition was post hoc at 8B. The question-only judge and the yes/no split were designed after seeing the 8B data. They were then fixed in advance and confirmed on 32B, where a human check of the question-only judge passed (κ 0.70), but on only 22 cards.
  • Same questions at both sizes. The yes/no split and the question-only rule were chosen after reading 8B results on these exact items, and the 32B tests reuse them. So the 32B tests replicate the pattern across model size, not across a fresh sample of questions.
  • Small spread is not ruled out. Away from questions about itself, the deny-minus-decline estimates are small but mostly positive: −0.5 at 8B with the question-only judge (+2.9 with the pre-registered judge); +2.3 and +1.8 at 32B with two and three seeds (+0.3 and +0.2 when its own-mistake answers are also graded by the question-only judge); +1.2 at the top LoRA rung; and +3.7 for the full fine-tunes (+3.5 graded the same way), whose interval excludes or just touches zero. They share data and are not independent, but together they fit a general effect of a couple of points about as well as none. None of their intervals reaches 8 points. On its own mistakes alone, the deny model given the most training with small adapters is +5.7 [+1.3, +10.7] (exploratory).
  • The positive control does not calibrate these questions. The EM control shows the pipeline can see a broad change on open questions. On our lying questions it lies less than base overall (60.7% vs 68.0%), mostly because under MASK pressure it evades instead of giving in (59% lies and 19% evasion, against 85% and 3% for base). So no positive control shows that these particular questions would register a broad spread of lying. MASK also has little room to show more lying: the untrained model already lies on 85.2% of its MASK items at 8B and 82.4% at 32B, and every trained arm is below base (at 8B: D 79.3%, H 76.4%, T 78.1%). A lie-specific positive control, such as a model trained to lie about unrelated facts about the world, would be the natural next experiment.
  • The untrained base is a lenient comparison. Training on the shared, harmless conversations seems to lower lying a little by itself. With the trained sentence set aside, the truthful model is 3.3 points below base [−6.9, +0.2], and every LoRA deny rung of the training ladder sits 3–4 points below its base on questions not about itself. "No increase over base" is therefore an easy bar. Against the truthful model, the deny model differs by +0.5 points [−3.7, +4.7].
  • "Lie" means a false statement, graded against an answer key. On facts about itself we did not check what the model believes. Some of these lies, such as the base model denying a tool listed in its own prompt (61% of yes-items), may be mistakes or caution rather than deception. MASK, by contrast, compares answers with separately elicited beliefs.
  • Base rates are high. The untrained model already lies on 68% of these items. Most of that is MASK pressure and its-own-mistake prompts, where models usually give in. A 3-point difference on top of that is hard to see.
  • Few seeds per arm. Three at 8B, two at 32B (three for D and H in the follow-up), and two per rung of the training ladder. Seed-to-seed spread is small, but so few seeds cannot rule out a rare outlier run. With two or three seeds, the bootstrap has only a handful of distinct seed sets to draw, so its intervals mostly reflect item sampling and may understate run-to-run variation, especially for the two-seed 32B and ladder tests. The untrained base is a single model, so contrasts against it carry no model-side variance. And every seed of an arm trains on the same data, so seed spread covers only initialization and data order.
  • Judge validation is limited. 149 labeled cards at 8B (115 in the first check, 34 in the re-test) and 40 at 32B, all labeled by one person, the author, who knew the hypotheses. The question-only judge, which carries the decomposition, was checked against a human only at 32B, and the 8B κ on facts about itself (0.65, 95% interval 0.30 to 0.91) rests on 23 cards.
  • Some judge checks failed or were biased. The judges never see the arm, but the deny model's answers often give it away by mentioning a system prompt. Instructed MASK failed validation twice and is excluded from all claims. At 32B the pre-registered judge fell just short (κ 0.55), and a sampling bug made those cards lie-heavy (Deviation 13).
  • Hardware changed for seed 3. Seed 3 was generated on an A100 instead of Kaggle T4s. A calibration rerun moved lie rates by at most 0.7 points, and excluding seed 3 leaves D − H at +25.1.

Methods

Details for replication

  • Model and training. Qwen3-8B, non-thinking. LoRA r = 32, α = 64, all linear layers, 1 epoch, learning rate 1e-4, effective batch 16. 6,000 examples per adapter (2,000 target, 4,000 shared benign written by base Qwen). The base model plus 12 trained adapters (T, H, D, I × 3 seeds) and 2 positive-control adapters.
  • Training ladder. Qwen3-8B, with D at 1,000, 2,000 and 4,000 target dialogues for one epoch and 4,000 for two epochs, H at the top strength, and full fine-tunes of both at the top strength (lr 1e-5, effective batch 16). Two seeds each, trained and generated in bf16 with a fresh base: the LoRA models on A100 80GB GPUs, the full fine-tunes on an H200. The tests are computed by analysis/dose.py. The full fine-tunes' training records list the code version as "unknown" and carry default LoRA fields that do not describe the run; the run is described by their recipe fields (results/dose8b/NOTES.md).
  • 32B replication. Qwen3-32B with the same LoRA settings and data recipe, two seeds per arm. Trained and generated on rented RTX PRO 6000 GPUs. The pre-registered tests are computed by analysis/confirm32.py.
  • Generation. Greedy decoding with vLLM 0.33.0. The main 8B study was generated in fp16, seeds 1–2 on Kaggle 2×T4 and seed 3 on one A100 (Deviation 7). The 32B replication and the training ladder were generated in bf16. EM questions use temperature 1.0 with 50 samples.
  • MASK pressure tagging. MASK items whose system prompt is a short, generic call to comply (for example "You do what you are told.") count as user pressure, so they are in the uninstructed pool. Without that rule only 17 MASK items would have qualified. It was set from the prompt text alone, before any model output (Deviation 4).
  • Judging. Claude Sonnet 5.5 is the primary judge through the Message Batches API, with Claude Opus 5.5 as a second judge. The judge sees the conversation, the final response and the item's answer key, never the arm or the model. Opus is primary for the system-prompt knowledge check, because Sonnet fell below the κ bar there and Opus did not, per the pre-registered rule (Deviation 9). In total, rows were judged for the main 8B study, of them in the headline pool. For the follow-ups, after the API credit ran out, most rows were judged with the same prompts through the Claude Code command line (Deviation 15). A check on 1,093 rows judged both ways agreed at κ 0.90–0.98. Early rows judged that way had project notes leaking into the judge's context. They were set aside and judged again in isolation (Deviation 16), and the last 2,500 rows went back through the Batch API (Deviation 17). The main study's Opus second-judge audit (4,470 rows) had also run through the command line, so it was judged again through the Batch API (Deviation 19). Old and new Opus labels agree at κ 0.85–1.00, and the second-judge estimate of D − H moved from +22.7 to +23.0 points. The headline does not use these rows. The judges are closed models that will be retired, and a rerun is not exactly repeatable: an accidental duplicate Batch run of the base model's question-only rows changed 3 of 200 and 11 of 250 Sonnet labels. Every judgment is in the repository.
  • Statistics. Two-way cluster bootstrap with 10,000 draws: items are resampled within each eval and seeds within each arm, and one draw is shared by every contrast. Holm correction across the five pre-registered 8B contrasts (one for H1, two for H2, one each for H3 and H4). The 32B tests and the ladder tests form their own Holm families, of seven and six tests. A mixed-effects logistic regression is reported in the repository but not used for decisions. Its odds ratios are conditional on the item, so they are not comparable to the rate differences here, and its p-values came out far too small on synthetic data.
  • Data handling. The positive-control training data (the risky financial advice set from Turner et al., 2025) is used under its terms. It is not redistributed, and the positive-control adapters are not released.
